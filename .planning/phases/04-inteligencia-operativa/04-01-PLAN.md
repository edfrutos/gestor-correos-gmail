# Phase 4 Plan: Inteligencia Operativa

## Objective

Convert the current Gmail helper into an operational decision panel: a single prioritized queue of actionable emails, fixed severity by category, provider-first grouping, and export to Markdown/JSON with an explicit scope choice at export time. Gmail remains readonly and local hide stays local-only.

## Must Haves

- The default view is a single actionable queue, ordered by severity and then by deterministic tie-breakers.
- Severity is fixed by category and must be visible on each actionable item.
- Provider/remitente is the primary grouping lens for the phase.
- Export supports Markdown and JSON only, and the user chooses scope at export time.
- Exported content must include summary, source, date, category, severity, and Gmail link.
- Local hide keeps the `Ocultar` wording and must not mutate Gmail.
- No new framework, no Gmail write actions, and no Gmail message cache in local state.

## Threat Model

- **Severity drift between backend and frontend:** queue order and visible labels can diverge if two rule tables exist. Mitigation: keep the severity map in one canonical place and expose normalized severity data in the Gmail message objects used by the UI.
- **Content injection in queue/export views:** Gmail subject/body/snippet values already pass through HTML rendering and export text. Mitigation: keep escaping centralized and do not interpolate raw content into HTML without the existing escaping helpers.
- **Export-scope ambiguity:** users may assume export means the filtered view when they intended the full set, or vice versa. Mitigation: force an explicit scope choice in the export modal before generating the file.
- **Readonly contract regression:** this phase must not slip into archive/delete/label behaviors. Mitigation: keep all actions local-view only and test that no Gmail write endpoint is introduced.

## Out of Scope

- Gmail write actions (`archive`, `delete`, labels, read-state changes).
- Manual per-email severity editing.
- Separate action-type inboxes.
- Weekly/monthly operational summaries.
- Editable classification rules from the UI.
- New frameworks or a rewrite of the single-file frontend.
